1. Project Goal
============================================================

EarthScan AI is a desktop web-based AI application for building damage
assessment from satellite imagery. The user uploads:

1. A pre-disaster satellite image.
2. A matching post-disaster satellite image.

The system predicts one of four image-level building damage classes:

- no-damage
- minor-damage
- major-damage
- destroyed

The project includes:

- Python backend using Flask.
- Trained CNN model.
- CNN+KNN hybrid model.
- Web-based frontend.
- Matplotlib evaluation visualizations.
- Visual-change heatmap.
- README and IEEE-format LaTeX report.

============================================================
4. Labeling Method
============================================================

The xBD post-disaster JSON files contain building polygons and damage
subtypes. Since this project is image-level classification, one label is
assigned to each image pair.

Method:
- Read post-disaster JSON file.
- Extract building damage labels.
- Choose the most severe damage level present in the image.

Severity order:
1. no-damage
2. minor-damage
3. major-damage
4. destroyed

Why this method was used:
Each satellite tile may contain multiple buildings with different damage
levels. Selecting the most severe visible damage gives one clear target label
for image-level classification.

5. Preprocessing Pipeline
============================================================

Script:
preprocess_balanced_pairs.py

Final processed folder:
processed_balanced_pairs_256/

Preprocessing steps:

1. Load pre-disaster image.
2. Load matching post-disaster image.
3. Convert OpenCV BGR format to RGB.
4. Resize both images to 256 x 256.
5. Convert to float32.
6. Normalize pixel values to [0, 1].
7. Concatenate pre and post images on channel axis.

Final input shape:
256 x 256 x 6

Channel layout:
- channels 0-2: pre-disaster RGB image
- channels 3-5: post-disaster RGB image

Split ratio:
- Train: 70 percent
- Validation: 15 percent
- Test: 15 percent

Verification:
verify_data_split.py confirmed:
- correct array shapes
- normalized values
- no split overlap
- no missing image paths
- augmentation allowed only for training

============================================================
6. Augmentation
============================================================

Script:
paired_augmentation.py

Augmentation is applied dynamically during training only.
Validation and test sets are not augmented.

Why:
Validation and test data must represent original unseen data. Augmenting them
would make evaluation unfair.

Important paired-image rule:
The same random spatial transform is applied to both pre and post images.

Why:
If pre and post images receive different rotations or shifts, the pair becomes
misaligned and the model may learn false differences.

Final augmentation config:
- rotation_range: 30
- width_shift_range: 0.1
- height_shift_range: 0.1
- zoom_range: 0.1
- shear_range: 5
- horizontal_flip: true
- vertical_flip: true
- brightness_range: 0.9 to 1.1
- channel_shift_range: 0.05
- fill_mode: nearest

7. Model 1: CNN
============================================================

Script:
train_evaluate_models.py

Model type:
Siamese-style CNN with MobileNetV2 backbone.

Input:
256 x 256 x 6 paired image.

Architecture concept:

1. Split the input into:
   - pre image: channels 0-2
   - post image: channels 3-5

2. Scale both images from [0, 1] to [-1, 1] because MobileNetV2 expects this
   input range.

3. Use one shared MobileNetV2 backbone for both images.

4. Extract:
   - pre-disaster features
   - post-disaster features
   - temporal difference features = post features - pre features

5. Concatenate these features.

6. Apply classification head:
   - Conv2D
   - BatchNormalization
   - GlobalAveragePooling
   - Dense layers
   - Dropout
   - Softmax output

Output classes:
4 damage classes.

Why CNN is suitable:
CNNs are strong for image classification because they learn spatial patterns,
textures, shapes, and visual changes in satellite imagery.

============================================================
8. Model 2: CNN+KNN
============================================================

Model type:
Hybrid deep feature extraction plus traditional ML classifier.

Process:

1. Train CNN model.
2. Use the CNN feature layer named "features" as a feature extractor.
3. Extract 128-dimensional deep features from each image pair.
4. Standardize features using StandardScaler.
5. Train KNeighborsClassifier.

KNN settings:
- n_neighbors: 5
- weights: distance

Why CNN+KNN is useful:
CNN learns image features. KNN classifies samples by comparing their extracted
feature vectors. This demonstrates both deep learning and classical machine
learning in one project.

Viva explanation:
CNN directly predicts using softmax. CNN+KNN uses CNN only to extract features,
then KNN performs the final classification.

13. Heatmap
============================================================

Heatmap type:
Visual-change heatmap

This is not pixel-level damage segmentation.

How it works:

1. Take pre image and post image after resizing/normalization.
2. Compute absolute RGB difference.
3. Average difference across RGB channels.
4. Smooth the difference map.
5. Normalize values.
6. Apply color map.
7. Overlay the heatmap on the post-disaster image.

Color meaning:
- Red/yellow: high visual change, possible damaged area
- Green/cyan: moderate visual change
- Blue/purple: low visual change

Important viva explanation:
The heatmap supports visual interpretation only. The final damage class comes
from CNN and CNN+KNN. The heatmap may highlight clouds, vegetation, lighting,
or terrain changes, so it should not be described as exact damaged building
segmentation.

20. How to Test the App
============================================================

Use matching pre/post images from:

Example naming pattern:
hurricane-michael_00000004_pre_disaster.png
hurricane-michael_00000004_post_disaster.png

Why matching IDs matter:
The model compares the same location before and after disaster. If images are
from different locations, the model compares unrelated areas and predictions
become unreliable.

21. Viva Preparation Questions
============================================================

Q: What problem does the project solve?
A: It predicts building damage severity from pre and post-disaster satellite
images.

Q: What are the input and output?
A: Input is a matching pre/post satellite image pair. Output is a damage class
with confidence scores from CNN and CNN+KNN.

Q: Why do pre and post images need the same ID?
A: Same ID means same location. The model learns disaster change from before
and after images of the same area.

Q: What is the final input shape?
A: 256 x 256 x 6.

Q: Why 6 channels?
A: 3 RGB channels from pre-disaster image plus 3 RGB channels from
post-disaster image.

Q: Which model is used in backend?
A: The backend uses run_02 from the final 5-run experiment because it achieved
the best CNN+KNN accuracy.

Q: Why report 5-run mean instead of only best run?
A: 5-run mean and standard deviation measure stability and satisfy the project
requirement. Best run is used only for the deployed app model.

Q: What is CNN+KNN?
A: CNN extracts deep visual features. KNN classifies the extracted feature
vectors.

Q: Is the heatmap exact damage localization?
A: No. It is a visual-change heatmap. It helps interpret pre/post differences
but the final damage class comes from the trained models.

Q: Why use class weights?
A: The final full paired dataset is imbalanced, so class weights reduce bias
toward majority classes.

Q: Does the app need the full dataset to run?
A: No. The app needs trained model files. The dataset is needed only for
retraining or for selecting sample images.

Q: What are the final results?
A: CNN+KNN achieved 69.14% +/- 2.84% accuracy over 5 runs. CNN achieved
67.10% +/- 1.73% accuracy.
